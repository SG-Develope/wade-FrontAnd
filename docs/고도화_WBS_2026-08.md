## 1. 목표 & 범위

WADE를 "실시간 수위 모니터링"에서 **"여가 탐색 + 회원 서비스"** 로 확장한다.

### Core (반드시 이번 달)

| # | 기능 | 한 줄 정의 |
|---|------|-----------|
| 1 | **여가지도 실연동** | 고캠핑 API(캠핑장) + 자전거길·산책로 선(Polyline)을 DB에 적재해 지도에 표시 |
| 2 | **CCTV 낮/밤 사진 매핑** | `cctvname` 매칭으로 낮/밤 사진 매핑, 18시 이후 밤 사진 표시 |
| 3 | **로그인 / 마이페이지** | 카카오 OAuth, 즐겨찾기, 캠핑장 상세(사진·정보), 내 문의 목록 |
| 4 | **관리자** | role 기반 인가, 사용자 목록 + 문의 전체 조회·답변 |
| 5 | **문의 (비실시간)** | 문의글 CRUD + 관리자 답변 |

### Stretch / 보류

- **S1 웹소켓 실시간 문의 채팅** — 버퍼 부족으로 이번 달은 어려움. 다음 사이클 1순위.
- **캠핑장 예약·결제** — 제외. 상세는 사진·정보 조회만.
- **지역 확장(합천·창녕·부산)** — 다음 사이클.

## 2. 전제 & 원칙

1. **디자인 먼저, 개발 나중.** W1에 Figma로 화면 확정 후 코드 착수.
2. **Figma는 본인이 직접 그린다.** Claude는 명세 제공 + MCP로 디자인→코드 변환.
3. **여가 데이터는 정적(1회 적재).** 캠핑장·코스는 스크립트로 한 번 받아 DB에 seed, 이후 DB만 조회. (수위·날씨·CCTV만 실시간.)
4. **자전거길·산책로 = 선(Polyline).** DB: `코스ID + 이름 + 좌표배열(jsonb)`. 캠핑장은 점(마커).
5. **문의는 비실시간 CRUD로 먼저 완성** → 웹소켓은 그 위에 얹는 Stretch.
6. 각 세션엔 **완료 기준(DoD)**. 애매하면 미루지 말고 그날 범위를 줄인다.
7. **커밋 규칙:** 세션 끝마다 최소 1커밋. 기능 단위 브랜치 권장(`feat/leisure-map` 등).
